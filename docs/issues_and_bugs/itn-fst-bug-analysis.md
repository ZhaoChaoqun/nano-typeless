# ITN FST "一些→1些" Bug 分析与修复报告

*2026-03-01*

---

## 1. 问题现象

Streaming Paraformer 启用 `itn_zh_number.fst` 后，"一些" 被错误转换为 "1些"：

```
原始文本: 我今天需要1些你的帮助
```

ASR 模型输出的是 "一些"，但经过 ITN FST 转换后 "一" 被替换为 "1"。

---

## 2. 根因分析

### 2.1 FST 文件分析

`itn_zh_number.fst`（25KB，来自 sherpa-onnx releases）是一个基于 UTF-8 字节级的 OpenFst 转换器，它识别以下中文数字字符并将其映射为阿拉伯数字：

| 中文 | 阿拉伯 | 中文 | 阿拉伯 |
|------|--------|------|--------|
| 零 | 0 | 五 | 5 |
| 一 | 1 | 六 | 6 |
| 二 | 2 | 七 | 7 |
| 三 | 3 | 八 | 8 |
| 四 | 4 | 九 | 9 |

以及位值词：百、千、万、十。

### 2.2 核心缺陷：无上下文感知

该 FST **没有任何上下文判断能力**。当遇到 "一" 时，无论后面跟的是量词（百、千、万、十）还是普通汉字（些、个、定、起、样），都会将 "一" 转换为 "1"。

通过 `fstcompose` + `fstshortestpath` 验证：

```
"一些"         → "1些"         (误转换)
"一个"         → "1个"         (误转换)
"一定"         → "1定"         (误转换)
"一起"         → "1起"         (误转换)
"一样"         → "1样"         (误转换)
"一直"         → "1直"         (误转换)
"一般"         → "1般"         (误转换)
```

### 2.3 更多问题

不仅仅是误转换，FST 的数字组合逻辑也有严重问题：

| 输入 | 期望输出 | 实际输出 | 问题 |
|------|---------|---------|------|
| 一百二十三 | 123 | 321 | 数字顺序反转 |
| 三百六十五 | 365 | 563 | 数字顺序反转 |
| 二零二六 | 2026 | 6202 | 数字顺序反转 |
| 一千 | 1000 | 0001 | 数字顺序反转 |
| 二百 | 200 | 002 | 数字顺序反转 |
| 五万 | 50000 | 00005 | 数字顺序反转 |
| 我有三个苹果 | 我有三个苹果 | 乱码 | 非数字文本被破坏 |
| 第一名 | 第1名 或不变 | 乱码 | passthrough 损坏 |

**结论：`itn_zh_number.fst` 基本不可用，存在系统性 Bug。**

### 2.4 原因推测

该 FST 似乎是一个非常简单的原型实现，只做了单字映射 + 简单的位值组合，但：
1. 没有上下文消歧（"一" 作为数词 vs "一" 作为副词/量词前缀）
2. 数字组合顺序可能是 FST 权重选择了错误的路径导致反转
3. passthrough 机制在多字节 UTF-8 场景下存在 Bug

## 3. 修复方案

### 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 禁用 FST，纯代码实现 ITN | 完全可控，支持上下文感知 | 需要自己实现转换逻辑 |
| B. 修复/替换 FST 文件 | 不改代码 | FST 调试困难，上下文消歧在 FST 中难以表达 |
| C. 禁用 FST，依赖 CSC 纠错 | 零成本 | CSC 不做 ITN，数字会保持中文 |

### 推荐方案：A — 禁用 FST，在后处理中用 Swift 代码实现上下文感知的 ITN

**理由：**
1. FST 本身存在多个系统性 Bug，不仅仅是误转换问题
2. 上下文感知的中文数字转换在代码中容易实现（正则 + 递归或状态机）
3. 后处理方式可以精确控制转换行为，避免误转换
4. SenseVoice Nano 和 Qwen3-ASR 的内置 ITN 效果良好，说明 ITN 适合在更高层级实现

### 实现计划

#### 步骤 1：禁用 FST

**文件**：`Sources/RecordingManager.swift`

在 `initializeStreamingParaformer()` 中，不再传递 `ruleFstsPath` 参数：

```swift
// 修改前
guard let recognizer = SherpaOnnxOnlineRecognizer(
    encoderPath: paths.encoderPath,
    decoderPath: paths.decoderPath,
    tokensPath: paths.tokensPath,
    ruleFstsPath: itnFstPath
) else { ... }

// 修改后
guard let recognizer = SherpaOnnxOnlineRecognizer(
    encoderPath: paths.encoderPath,
    decoderPath: paths.decoderPath,
    tokensPath: paths.tokensPath
    // ITN 改为后处理阶段实现，不使用 FST
) else { ... }
```

同时移除 `loadITNFst()` 调用。

#### 步骤 2：实现 ChineseNumberConverter

**新增文件**：`Sources/ChineseNumberConverter.swift`

```swift
class ChineseNumberConverter {
    /// 将文本中的中文数字转换为阿拉伯数字
    /// 仅转换明确的数值表达，不转换 "一些"、"一个" 等非数值用法
    static func convert(_ text: String) -> String
}
```

核心逻辑：
1. 用正则匹配连续的中文数字串（如 `[零一二三四五六七八九十百千万亿]+`）
2. 对匹配结果检查上下文：
   - **仅转换**：独立数值（如 "一百二十三"、"三十五"）
   - **不转换**：后面跟常见量词/副词后缀（些、个、定、起、样、直、般、共、同、切、致、旦、度、味、概、贯、律、向、如、经、并、再、边、面、点、下、会、次）时，单独的 "一" 不转换
   - **转换**：后面跟位值词或另一个数字时转换（如 "一百"、"三十五"）
3. 中文数字串到阿拉伯数字的转换算法：
   - 处理位值：十(10)、百(100)、千(1000)、万(10000)、亿(100000000)
   - "二零二六" 这种直接拼接的序列 → "2026"
   - "一百二十三" 递归计算 → 123

#### 步骤 3：集成到后处理管线

**文件**：`Sources/RecordingManager.swift`

在 `stopRecording` 的后处理链中，对 Streaming Paraformer 增加 ITN 步骤：

```
ASR flush → 原始文本 → [ITN (代码)] → [CSC 纠错] → [标点处理] → 最终文本
```

仅对 Streaming Paraformer 启用代码 ITN（SenseVoice 内置 ITN，Qwen3 内置全部后处理）。

#### 步骤 4：清理

- 移除 `RecordingManager.swift` 中的 `loadITNFst()` 方法
- 移除 `SherpaOnnxManager.swift` 中的 ITN FST 下载相关代码（可选，保留也不影响）
- 移除 `SettingsView.swift` 中的 ITN FST 下载 UI（如有）

## 4. 中文数字转换规则

### 4.1 应转换的数值表达

| 输入 | 输出 | 规则 |
|------|------|------|
| 一百二十三 | 123 | 位值计算 |
| 三十五 | 35 | 位值计算 |
| 二零二六 | 2026 | 直接拼接 |
| 一千零五 | 1005 | 位值+零占位 |
| 一万两千 | 12000 | 位值计算（两=2） |
| 三百六十五 | 365 | 位值计算 |

### 4.2 不应转换的表达

| 输入 | 理由 |
|------|------|
| 一些 | "一" 作为不定代词 |
| 一个 | "一" 作为量词修饰 |
| 一定 | "一定" 是副词 |
| 一起 | "一起" 是副词 |
| 一样 | "一样" 是形容词 |
| 一直 | "一直" 是副词 |
| 一般 | "一般" 是形容词 |
| 一切 | "一切" 是代词 |

### 4.3 判断规则

**转换条件**（满足任一）：
- 匹配串长度 ≥ 2 且包含位值词（十百千万亿）
- 匹配串全由 "零一二三四五六七八九" 组成且长度 ≥ 2（如 "二零二六"）
- 单个数词前后都是非中文数字字符，且上下文明确是数值（如 "第三名" 中的 "三"）

**不转换条件**（满足任一）：
- 单个 "一" 后面跟非数字非位值汉字
- 匹配串长度 = 1 且为 "一"，后面跟常见搭配词

## 5. 验证计划

1. 基础数字转换：
   - "一百二十三" → "123"
   - "二零二六年" → "2026年"
   - "三十五" → "35"
   - "一千零五十" → "1050"

2. 不应转换的验证：
   - "一些" → "一些"（不变）
   - "一个苹果" → "一个苹果"（不变）
   - "一定要来" → "一定要来"（不变）

3. 混合文本：
   - "我有三百二十一个苹果" → "我有321个苹果"
   - "第一名得了九十八分" → "第一名得了98分" 或 "第1名得了98分"
